# Отчет по практической работе CI/CD

## 1. Цель работы

Изучить работу GitHub Actions и проследить, как изменения в коде влияют на автоматическое тестирование и сборку проекта.

## 2. Первый успешный запуск

После загрузки сайта и настройки `ci.yml` GitHub Actions автоматически запустил проверку.

Все 4 теста прошли успешно. После этого выполнилась сборка сайта и был создан артефакт `lesson-site`.

Первый запуск: https://github.com/VonOfficial/cicd-first-run/actions/runs/43419366646

## 3. Создание ошибки

В файле `site/index.html` я специально заменил `href="style.css"` на `href="missing.css"`.

**Прогноз до изменения:** тест `test_stylesheet_exists` не пройдёт, потому что файла `missing.css` не существует. Сборка сайта и сохранение артефакта не выполнятся.

**Фактический результат:** прогноз подтвердился. Один из четырёх тестов завершился ошибкой.

Название теста: `test_stylesheet_exists`

Причина ошибки: `AssertionError: False is not true : Missing stylesheet: missing.css`

После неудачного теста шаги `Build site` и `Save site artifact` были пропущены, поэтому новый артефакт не создался.

Коммит: `0474375cad2eec9f3b10ba09b0ec5be4ac473b5b`

Красный запуск: https://github.com/VonOfficial/cicd-first-run/actions/runs/43422150225

## 4. Исправление ошибки

Я вернул правильную ссылку `href="style.css"` и сохранил изменение отдельным коммитом.

После исправления все 4 теста снова прошли успешно. Сборка сайта и сохранение артефакта также завершились успешно.

Коммит: `2fcdba0c7800e1796746c046323b63950c1166df`

Зелёный запуск: https://github.com/VonOfficial/cicd-first-run/actions/runs/43422817128

При этом предыдущий красный запуск остался в истории GitHub Actions.

## 5. Изменение номера аудитории

В отдельном коммите я изменил номер аудитории с 301 на 302.

**Прогноз:** все тесты пройдут, поскольку они не проверяют номер аудитории.

**Результат:** все тесты прошли успешно.

Коммит: `5ae7fbad7caa862104b4a0794917a8b8de2bc393`

Запуск: https://github.com/VonOfficial/cicd-first-run/actions/runs/43428107521

Зелёный результат не доказывает, что номер аудитории правильный. Тесты проверяют только определённые условия: заголовки, тему занятия и наличие файла стилей. Номер аудитории в них не проверяется.

## 6. Где выполнялись тесты

Тесты запускались не на моём компьютере, а на GitHub-hosted runner с Ubuntu, который автоматически выделяется для выполнения workflow.

Результаты сохраняются в GitHub Actions, потому что workflow выполняется на инфраструктуре GitHub. Там можно посмотреть журналы, ошибки, коммиты и историю запусков.

Артефакт `lesson-site` содержит собранный сайт и файл `release.json`, в котором указан коммит исходного кода. Скачивание артефакта не означает публикацию сайта в интернете.

## 7. Вывод

В ходе практической работы я настроил CI через GitHub Actions, проверил успешное выполнение тестов, специально создал ошибку и затем исправил её.

Я понял, что CI помогает автоматически находить определённые ошибки в проекте, но успешное прохождение тестов не гарантирует, что в программе вообще нет ошибок. Всё зависит от того, что именно проверяют тесты.
